# 네트워크 연결 설정 (사내망 TLS 이슈 대응)

## 배경
LG CNS 사내망은 SSL 검사(TLS Inspection) 프록시를 사용한다. 이 프록시는 자체 루트 인증서로
HTTPS 트래픽을 가로채서 재서명하는데, Windows OS는 이 루트 인증서를 신뢰하도록 이미
구성되어 있지만 Node.js는 OS 인증서 저장소를 쓰지 않고 자체 내장 CA 목록만 사용한다.

그 결과 Node.js(Next.js `next dev` 서버 포함)에서 외부 HTTPS 요청(Supabase, TMDB 등)을
호출하면 다음과 같은 에러가 발생한다.

```
TypeError: fetch failed
  [cause]: Error: self-signed certificate in certificate chain
    code: 'SELF_SIGNED_CERT_IN_CHAIN'
```

PowerShell(`Invoke-WebRequest`)처럼 OS 인증서 저장소를 쓰는 도구는 같은 요청에서 문제가
없기 때문에, "브라우저/curl은 되는데 Node만 안 된다"가 이 이슈의 특징적인 증상이다.

## 조치 내용

### 1. 사내 루트 인증서를 PEM으로 내보내기
Windows `LocalMachine\Root` 저장소에 설치된 LG CNS 인증서를 찾아 PEM 번들로 저장한다.

```powershell
$certs = Get-ChildItem -Path Cert:\LocalMachine\Root | Where-Object { $_.Subject -match "LG CNS" }
$outFile = "C:\Users\86168\Desktop\myMovieProject\corp-ca-bundle.pem"
if (Test-Path $outFile) { Remove-Item $outFile -Force }
foreach ($cert in $certs) {
  $b64 = [System.Convert]::ToBase64String($cert.RawData, [System.Base64FormattingOptions]::InsertLineBreaks)
  "-----BEGIN CERTIFICATE-----`n$b64`n-----END CERTIFICATE-----" | Add-Content -Path $outFile -Encoding ascii
}
```

- 결과 파일: `corp-ca-bundle.pem` (프로젝트 루트)
- `.gitignore`의 `*.pem` 규칙에 의해 Git 추적 대상에서 제외된다. 인증서 자체가 비밀정보는
  아니지만, 장비마다 발급 상태가 다를 수 있어 커밋하지 않고 각자 로컬에서 생성한다.

### 2. Node.js에 CA 경로 알려주기 (`NODE_EXTRA_CA_CERTS`)
Node는 `NODE_EXTRA_CA_CERTS` 환경변수에 지정된 PEM 파일을 기본 CA 목록에 추가로 신뢰한다.

**영구 설정 (Windows 사용자 환경변수, 재부팅/새 터미널에도 유지됨)**

```powershell
[System.Environment]::SetEnvironmentVariable(
  "NODE_EXTRA_CA_CERTS",
  "C:\Users\86168\Desktop\myMovieProject\corp-ca-bundle.pem",
  "User"
)
```

> `setx` 명령이 없는 제한된 셸 환경에서는 위 `[System.Environment]::SetEnvironmentVariable`
> 방식을 사용한다. 설정 후 **새로 여는 터미널/IDE부터** 적용되며, 이미 열려 있던 터미널에는
> 반영되지 않는다.

**임시 설정 (현재 세션에만 적용, 확인용)**

```powershell
$env:NODE_EXTRA_CA_CERTS = "C:\Users\86168\Desktop\myMovieProject\corp-ca-bundle.pem"
npm run dev
```

### 3. 정상 동작 확인
```powershell
node -e "fetch('https://qmwgnrgnhgjxbbywhsnu.supabase.co/auth/v1/health').then(r=>r.text()).then(t=>console.log('OK',t)).catch(e=>console.log('FAIL', e))"
```
`FAIL ... SELF_SIGNED_CERT_IN_CHAIN` 대신 `OK {...}` (401 계열 정상 응답)가 나오면 해결된 상태다.

## 재발 조건 / 체크리스트
아래 상황이 생기면 이 문서를 다시 참고해서 같은 절차를 반복한다.

- [ ] 새 PC/새 사용자 계정으로 개발 환경을 옮겼을 때 (사용자 환경변수는 계정별로 분리됨)
- [ ] 사내 IT 정책으로 SSL 검사 루트 인증서가 갱신/재발급되었을 때 (`corp-ca-bundle.pem` 재생성 필요)
- [ ] Node.js 버전을 올렸는데 다시 `fetch failed`가 재현될 때
- [ ] `NEXT_PUBLIC_SUPABASE_URL`, `TMDB_API_KEY` 등 외부 API 연동 설정을 변경/추가할 때
      (새 외부 도메인도 같은 사내 프록시를 통과하므로 동일 증상이 날 수 있다)
- [ ] `network`, `fetch failed`, `CERT`, `SELF_SIGNED`, `proxy` 관련 에러를 다시 마주쳤을 때

## 참고
- 이 설정은 프로젝트 코드가 아니라 **로컬 개발 환경(사용자 계정) 설정**이다. 저장소를 클론한
  다른 팀원도 각자 자신의 PC에서 1회 설정해야 한다.
- Supabase Auth 이메일 인증 OFF, `reviews` 테이블/RLS 마이그레이션 등 애플리케이션 레벨
  설정은 이 문서의 범위가 아니다 (`supabase/migrations/0001_reviews.sql` 참고).
